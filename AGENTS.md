# Lycoris — краткие правила для Codex/Hermes (полные: CLAUDE.md, читай только нужный раздел)
- C# / WPF / .NET 10, Windows. Проект: src/Lycoris, тесты: tests/Lycoris.Tests. UI-тексты по-русски через `Loc.T("…")` (русский = ключ), английский в src/Lycoris/Core/Localization/en/*.json.
- Сборка: `dotnet build -c Debug` (0 предупреждений). Тесты: `dotnet test --no-build`. Самопроверка: `Lycoris.exe --selftest <tempdir>` (код 0, ru и `--lang en`).
- Поиск: `rg`/`fd`, не читать файлы целиком. Правки минимальные и точечные. Перед массовой заменой — `rg`/`sg` для охвата.
- Безопасность: любое изменение системы только через `Core/ChangeSession` (журнал + откат). Не трогать реальную систему в тестах (фейки, `LYCORIS_HW_TESTS` только по разрешению). Без прав админа читать можно, писать нельзя.
- Не пушить, не выпускать релизы, не менять CLAUDE.md/.claude без задания. Ветка и worktree — только свои.
- Критичное (админ, драйверы, сеть, службы, реальное железо, удаление файлов) — не делать, написать вопрос в отчёте.
- Отчёт по-русски, коротко: что сделано, пути файлов, результат сборки/тестов, ветка и последний коммит.
- Связь с Hermes: фоновые/по расписанию задачи и уведомления — `hermes -z "задача"` (разово). Hermes вызывает Codex через `codex exec`.

## Порядок работы (правило владельца, 03.11.2026)
Никогда не начинай с кода. Сначала изучи: прочитай нужный код, правила проекта и документацию платформы/библиотеки, найди, как это уже сделано в проекте (не дублируй готовые модули — сначала поищи существующий). Затем коротко запиши решение и почему. Только после этого пиши код, а потом проверь его на деле (сборка, тесты, снимок/запуск).
