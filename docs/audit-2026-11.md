# Audit 2026-11: correctness, safety, robustness (non-visual code)

Scope: `Core/`, `Tweaks/`, `Modules/*` logic, `Shell/` logic. Method: adversarial read of every module against
`CLAUDE.md` and `docs/research/*.md`, independent review passes per area, every claim re-checked in the code before a fix.
Fixes keep their own tests in `tests/Monolith.Tests/Audit202611Tests.cs` (and existing test files).
Status: **Fixed** = changed and tested; **Not fixed** = reason given; **Info** = checked, behaviour is intentional.

## Not fixed (with reason)

| Finding | Reason |
|---------|--------|
| `WingetClient`: gate is released when a modifying run exceeds 30 min (process intentionally left running), a following winget call can start in parallel; Drivers `RunWingetItemAsync`/`InstallToolAsync` have no «still running» stop like Apps. | Needs a design change (track the live process); the case is a 30-minute install. Apps already stops its queue. |
| winget `0x8A150001` is retried once for install/upgrade. | winget install of an already installed id is idempotent (`AlreadyInstalled`), the retry fixes spurious internal errors. Not a defect. |
| `VendorDownloads`: unverifiable signature (timeout of the PowerShell check) deletes the downloaded file. | Safe direction (never keep an unverified installer); costs a re-download. Redirect hosts are checked after headers arrive, before any body is read; only the `Referer` header reaches the intermediate host. |
| `DriversViewModel.InstallToolAsync` installs a Store package with the admin token (Apps uses `UnelevatedWinget`). | Needs the Apps routing moved to a shared place; only the NVIDIA app is affected. |
| `NativeCleaner` opens with `FILE_SHARE_ALL` + POSIX delete: files opened by another process with `FILE_SHARE_DELETE` are unlinked. | Changing our share mode does not change this (their handle allows delete); the files are older than the age limit and in temp folders. Documented in `docs/research/cleaner.md §2.2` as «locked = skipped», which holds for normal sharing. |
| Cleaner manifests hold one entry per file (millions of files = ~2 GB). | Needs a streaming redesign; guarded by the age/size filters and only for pathological temp folders. |
| `ChangeJournal`: an unknown `ChangeKind` name (downgrade after a newer build) makes the journal «damaged». | Downgrade scenario; the new journal flow keeps the old files. A tolerant converter changes the on-disk contract: owner decision. |
| Two elevated Lycoris in two sessions (RDP + console) can overwrite each other's journal (`Local\` mutex). | Rare; needs a `Global\` mutex or file locking, which changes the single-instance behaviour. |
| Journal: a crash between `Add` and the system write leaves an orphan record (OldValue = live value). | Reverting it is harmless (writes back the same value); a layer hand-over to an orphan only delays the older revert. Needs a record state flag (schema change). |
| `AppPaths.SecureMachineDir` rewrites the ACL of every child at each elevated start. | Measured nothing; the cost grows with driver backups. Candidate for the startup-performance work. |
| One restore point per batch with the 24 h limit lifted. | By design (every batch is undoable); pruning policy is an owner decision. |
| `ServicesViewModel`/`RestoreViewModel` show a confirmation dialog inside `RunBusyAsync` (holds a `JournalChange` lease while the dialog is open). | Rule violation but only delays other journal operations while a dialog is open; a safe refactor touches ~10 call sites. |
| `hvci-off` Detect reads only `Enabled == 1`; HVCI that Windows enabled without the value would show «применено». | Cannot be verified without real hardware; the apply path does nothing unless `Enabled == 1`, so no change is made. |
| `power-plan-balanced-x3d` ignores an OEM «AMD Ryzen Balanced» plan (unlike `power-plan-balanced`); `start-hide-recommended`, `start-web-recommendations-off` have no edition gate (docs: Pro/Enterprise/Education). | Behaviour depends on the AMD driver and SKU, unverifiable here. Marked for a manual check on real machines. |
| Doc/text drift: `gaming_tweaks.md` «never pre-selected» for efficiency power modes vs `DefaultIn = Efficiency` (follows `general_tweaks.md` §11); `Tweak.Risk` comment «Optional … unchecked». | Documentation only. |
| `RegistryHelper.ReadInt/ToLong/ValueEquals` accept REG_SZ digits as DWORD; number parse/format uses the current culture (journal values are digits, so only sv-SE-like minus signs could matter). | No tweak mixes types; fixing parse culture changes the on-disk reading rules (owner decision). |
| `UnelevatedWinget` trusts `.exit/.log` files in the user's `%TEMP%`. | Not an escalation (it can only mislead the result); needs a different channel. |
| Dashboard/Services/Startup UI-collection and COM-scan findings with low confidence (startup scanner on slow UNC paths, `LogonTaskScanner` one failing folder, `ReloadAsync` one failing task). | Not reproduced; no evidence of a crash. |

## Info (checked, fine)

Tweak catalog vs research (no DO-NOT-INCLUDE item exists, no Advanced item in a profile, apply/revert of every registry tweak is tested
against the redirected registry); `PathGuard` and `NativeCleaner` handle-based deletion (reparse points, final path, size/time, hard links);
journal storage (atomic save, `.bak`, quarantine when the folder is insecure, layered hand-over); `AdminIntent` allow-list; `Loc.Tf` never takes user data as a format;
display guard (restores the mode if Lycoris dies); EcoQoS state restore by handle (PID reuse safe); `OperationCoordinator` admission; settings validation.

## Observed once

A full `dotnet test` run once stayed 10 minutes in `testhost` (a hung test) while a second build was running in parallel;
six further runs finished in 30-45 s. The hung test was not identified (candidates: tests that wait on a dispatcher/timer under load).
