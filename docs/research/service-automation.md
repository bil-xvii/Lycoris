# Управление службами через помощника

Решение от 18.11.2026. Продолжает ограничения `services.md`; слово «ненужная» не является техническим признаком.

## Команды и границы

- «Включи службу …»: разрешить запуск по требованию, если служба отключена. Существующий автоматический запуск сохраняется.
- «Отключи службу …»: запретить последующий запуск с сохранением прежнего типа в журнале.
- «Запусти службу …» и «Останови службу …»: отдельные действия над текущим состоянием. Они не подменяют изменение типа запуска.
- Помощник показывает фактическое состояние после действия. Смена типа запуска сама по себе не запускает и не останавливает службу.

Распознавание команд выполняется локальным конечным разбором до обращения к языковой модели. Модель по-прежнему
может только объяснять и предлагать переходы. Она не выдаёт команды оболочки и не получает права на запись в систему.
Рабочая цель — точное системное или отображаемое имя из свежего списка SCM. Неоднозначность, отрицание, составная
команда или неподтверждённые данные не разрешают изменение. Повтор после UAC содержит только операцию и уже найденное
системное имя; повторное разрешение по отображаемому имени запрещено.

Каждое изменение проверяет защищённые службы, тип и конфигурацию, управление организацией, доступ, режимы,
зависимости и актуальность подтверждённого плана. После ожидания очереди, подтверждения и создания точки
восстановления проверки повторяются. Отключение не заменяет состояние «неизвестно» значением «зависимостей нет».
Запуск и остановка не выполняются каскадом по произвольно расширенному набору служб.

## Службы, которые могут понадобиться

Используются существующий проверенный каталог, условия и профили. Цель «Вручную» не заменяется автоматически
на «Отключена». Работающие службы не останавливаются при применении рекомендаций. Условные функции, например
печать и Xbox, не считаются ненужными по числу запусков или наличию мощной видеокарты.
Исходные тип запуска и отложенный запуск сохраняются через `ChangeSession` и восстанавливаются из журнала.

## Удаление записей оставшихся служб

Это отдельный, ограниченный сценарий. Отсутствие EXE или записи в списке приложений не доказывает успешное
удаление программы. Для автоматического разбора допускается только проверенный рецепт продукта и явное
подтверждение владельцем, что указанный продукт уже удалён и не нужен. До подтверждения выполняется только чтение.

Первый рецепт — точное имя `Everything`, известный путь `Everything\Everything.exe` внутри стандартного
Program Files и документированный аргумент `-svc`. Это не универсальное разрешение удалять службы с неизвестным
издателем или похожим именем. Другие продукты остаются неподдержанными до отдельного исследования и тестов.

Удаляемая запись должна быть остановленной, отключённой, самостоятельной службой LocalSystem с полностью
воспроизводимой простой конфигурацией. Зависимости, расширенные или неизвестные настройки, защита, нестандартные
права, непроверенный путь, существующий EXE, недоступный том или ошибка проверки запрещают операцию.
Пользователь видит точное имя и путь; файлы программы при этом не удаляются.

Нативная проверка на одноразовой Windows 11 показала два ограничения платформы. Запрос preferred NUMA node
может вернуть Win32 `87`; этот код сам по себе не означает отсутствия настройки. Допускается только совокупность
этого ответа, успешного определения максимального NUMA-узла `0` и точного штатного набора значений реестра
без дополнительных значений и подразделов. Вид подтверждения входит в аутентифицированный снимок;
перед восстановлением топология проверяется снова. Неизвестный ответ или изменившаяся топология запрещают создание.

Поддерживаемый дескриптор службы содержит владельца и группу SYSTEM, точный штатный DACL и единственную
наблюдавшуюся у свежей службы запись SACL об отказах доступа Everyone. Пустой или изменённый SACL не допускается.
Lycoris не переписывает права: после обычного `CreateService` сверяется полный дескриптор и остальная конфигурация.
Другой системный вариант остаётся неподдержанным, пока его воспроизводимость не доказана отдельно.

До `DeleteService` записываются типизированная запись журнала и аутентифицированная резервная конфигурация.
Журнал не получает права восстанавливать произвольные `ImagePath`, `ServiceDll` или команды. Конфигурация хранится
отдельно в HKLM с проверенными правами Administrators/SYSTEM и привязкой к записи, пакету изменений и компьютеру.
Существующие небезопасные права хранилища не исправляются с последующим доверием к старым данным.

Вспомогательный рекурсивный экспорт реестра через `reg.exe` отключён: повторное открытие текстового пути
внешним процессом нельзя привязать к уже проверенному дескриптору. Это исключает экспорт закрытого хранилища
через подменённые ссылки. Обычный откат настроек реестра и SPI использует типизированные снимки журнала,
а не дополнительные `.reg`-файлы, и сохраняется.

SCM может лишь пометить службу для удаления: завершение ожидает закрытия дескрипторов. Это отдельный результат,
не сообщение «удалена». Откат разрешён только при подтверждённо свободном имени и проверенной резервной записи;
одноимённая новая служба не заменяется. Восстановленная запись остаётся отключённой. Наличие её файла не обещается.

## Проверка

Модульные проверки используют подставные SCM, журнал и защищённое хранилище. Разрушительные циклы не выполняются
над службами компьютера владельца. Для проверки настоящего SCM требуется отдельный одноразовый Windows runner,
который создаёт только свою помеченную тестовую запись и отказывается работать с уже существующей службой.
Результаты сборки, тестов и выполнения фиксируются отдельно; этот документ сам по себе их не подтверждает.
