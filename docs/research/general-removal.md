# Общее определение приложений и запуск одной кнопкой

Решение от 19.11.2026 для следующей версии после 1.0.29: заменить положительный перечень из трёх имён проверкой фактов об установленном приложении. Полный снимок классических регистраций и пакетов текущего пользователя показывает кандидатов, защищённые компоненты и записи, для которых сведений недостаточно. Отсутствие доказанной необходимости приложения не доказывает, что пользователь им не пользуется.

Для автоматического удаления классической программы нужны точная свежая регистрация установщика, собственная папка, проверяемая ручная точка запуска обычного GUI-приложения и согласованная подпись/метаданные. Работающая программа, общая папка или код продукта, системная/защитная/драйверная роль, известные зависимости, аппаратное управление, средства установки и спорные фоновые функции исключают автоматический выбор. Неизвестные отношения показываются как требующие проверки. Личные документы и содержимое переписок не читаются.

Идентичность исполнения задаётся собственным локальным ID WinGet `ARP\Machine|User\X64|X86\<исходный ключ>`, а не похожим именем в каталоге. В WinGet 1.29.380 точный поиск сохраняет исходный установленный объект. Обратная корреляция с официальным каталогом не подменяет его: схема каталожного PackageIdentifier запрещает обратную косую черту. Дополнительно передаются исходный ProductCode, область и версия; повтор одного кода в разных представлениях исключается. Неподходящая версия или неизвестный результат дают отказ без ослабляющего повторного запроса. Для разных деинсталляторов используется штатный интерактивный режим: выбор удаления личных данных нельзя угадывать.

Для этой операции требуется WinGet не ниже 1.8.1791: в 1.6 локальным ID служил только исходный ключ, а фильтр установленной версии не применялся. Первый стабильный выпуск с безусловным префиксом ARP и выбором установленной версии — [1.8.1791](https://github.com/microsoft/winget-cli/releases/tag/v1.8.1791), проверены [ARPHelper](https://github.com/microsoft/winget-cli/blob/v1.8.1791/src/AppInstallerRepositoryCore/Microsoft/ARPHelper.cpp#L395-L414), [выбор установленной версии](https://github.com/microsoft/winget-cli/blob/v1.8.1791/src/AppInstallerCLICore/Workflows/WorkflowBase.cpp#L1384-L1408) и [ограничение каталожного ID](https://github.com/microsoft/winget-cli/blob/v1.8.1791/schemas/JSON/manifests/v1.7.0/manifest.version.1.7.0.json#L7-L11). Общий минимум 1.6 для остальных возможностей Lycoris сохраняется. Переназначение версии составным источником может привести к безопасному отказу: запрос без версии повторно не отправляется.

Прочитанная команда удаления проверяется буквально, без раскрытия переменных окружения: окружение поднятого Lycoris и обычного Explorer может отличаться. Известные процессы учёта памяти виртуальных машин `Vmmem`/`VmmemWSL` в сеансе 0 и без пользовательского файла не считаются неизвестным работающим приложением; для остальных непрочитанных процессов проверка остаётся неполной. Это [синтезированные Windows процессы учёта виртуальных машин](https://devblogs.microsoft.com/oldnewthing/20180717-00/?p=99265), текущее имя также указано в [документации WSL](https://learn.microsoft.com/en-us/windows/wsl/troubleshooting-guide).

Признаки ручного запуска, подписи и назначения файла используются и для автозапуска. Проверка отключения отличается от удаления: работающий GUI-процесс можно оставить открытым и убрать только его будущий запуск. Служебная, защитная, аппаратная, синхронизирующая или иная необходимая фоновая роль не объявляется обычным окном программы. У подтверждённой записи меняется только разрешение запуска, с точным откатом и повторной проверкой непосредственно перед записью.

Пакеты MSIX/Store включаются в обзор и проверку зависимостей. Пакеты-фреймворки и защищённые компоненты сохраняются. Обычные пакеты без доказанного безопасного способа удаления остаются для штатного диалога Windows: удаление пакета может также затронуть данные приложения и неиспользуемые зависимости. Поддерживаемые доказанные задачи автозапуска пакетов допускают отдельное обратимое отключение; состояния политики не меняются.

Основная кнопка выполняет проверку, автоматически отмечает подходящие цели, освобождает измерительную операцию и открывает точное подтверждение. После согласия она сама ставит действие в очередь и выполняет его. Отдельное нажатие «Выполнить» после подбора не требуется. Предпросмотр сохранён для исключения отдельных строк. Двойной запуск, смена режима/аккаунта/вкладки и изменение подтверждённых объектов не должны менять уже согласованный пакет.

Проверки: незнакомые приложения разных имён без добавления в каталог; защищённые и неизвестные роли; дубли и подмена исходной регистрации; отключение работающего окна без его завершения; точный откат; отмена и однократность основной кнопки; линейная обработка снимка без двух CLI-вызовов на каждую программу при подборе. После начала пакета длительное штатное удаление не делает оставшиеся неизменные объекты автоматически просроченными: каждый из них проверяется заново. Реальные приложения владельца в тестах не удаляются.
