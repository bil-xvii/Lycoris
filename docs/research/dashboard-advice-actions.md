# Советы «Панели»: путь, действие и защита игровых компонентов

Решение 19.11.2026. Ветка `codex/dashboard-advice-actions`, база `ee072a0` (1.0.30). Параллельный чат готовит помощника и Store cleanup в своей рабочей копии; здесь выполняется отдельная задача, без перезаписи его файлов и без номера выпуска до объединения.

Использовать существующие HealthRules/CheckAction, подсказки AssistantDiagnostics, переходы Ui.RequestFocus и владельцев действий. У совета показывать точный путь и следующий шаг. Кнопка открытия всегда только открывает нужное место; поддерживаемое исправление использует существующий механизм подтверждения, повторной проверки и журнала. Неизвестную причину сбоя нельзя автоматически «чинить»: открывается монитор стабильности и объясняется, какую запись сверить. Для BIOS и физических подключений доступны сведения/руководство, без записи настроек оборудования.

Исправить маршрут `section:drift` и сохранить намерение фильтра при холодном асинхронном чтении журнала. «Исправить всё безопасное» включает только каталог Safe; Optional не попадает туда через замену GPU/настройки. После подтверждения и ожидания очереди план должен оставаться актуальным.

Защита: загрузочная задержка или ошибка чтения файла не доказывают необязательность автозапуска. Автоматическое отключение использует имеющееся строгое доказательство назначения/подписи/ручного запуска. Защищённые игровые/системные/аппаратные записи не отключаются обходным старым путём или повторным применением старой отметки. Службы игровых платформ, входа и античита сохраняются; подтверждённые пробелы закрываются в общей проверке, без новых service writers. Реальные программы, службы и автозапуск владельца не меняются в тестах.

Первичные источники: [perfmon /rel](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/perfmon), [что доказывает Event ID 41](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/event-id-41-restart), [EA app и фоновая служба](https://help.ea.com/en/articles/platforms/ea-app-how-to-close-background-apps/), [EA Javelin и запуск игр](https://help.ea.com/en/articles/platforms/pc-ea-anticheat/). Точные идентификаторы служб/пакетов проверяются по платформенным данным, имя процесса не подменяет SCM identity.

## Дополнительная проверка надёжности системных действий

По уточнению владельца о глубокой интеграции Windows проверены существующие UAC, автозапуск, журнал и подтверждение результатов. Нативные SCM/реестр/Task Scheduler/API питания уже используются, повторная подсистема или вмешательство в ядро не нужны. Максимальные права обычного приложения предоставляются штатным UAC; существующая настройка ElevateAtStartup остаётся доступной владельцу.

Найдены два воспроизводимых пробела: общий путь панели показывает успех до свежего чтения результата; повышенный headless observer при выходе мог сохранить устаревший полный журнал. Исполнители исправляют подтверждение результата и владение записью. Для нескольких сеансов Windows требуется единственный защищённый владелец машинного журнала перед загрузкой изменяемого состояния. Решение рассматривается независимым reviewer до реализации; проверки используют временные журналы и поддельные системные операции.

Платформа: [UAC и полный административный токен](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/how-it-works), [FileShare.None](https://learn.microsoft.com/en-us/dotnet/api/system.io.fileshare?view=net-10.0).
