# Производительность, 02.11.2026

Задача владельца: «чтобы программа была совершенной» — запуск, память, простой процессора, размер.

## Метод

- Сборка: `dotnet publish -c Release -r win-x64 --self-contained true` (то же, что `tools\publish.ps1`: single-file, сжатие, ReadyToRun) во временную папку; установленный exe не трогали.
- Измерение: `tools\perf-measure.ps1 -Exe <путь> [-IdleSec 60] [-Minimize]` запускает exe с флагом `--startup-timing <файл>` (QA: лишняя копия, только чтение,
  игнорирует замок одного экземпляра, ничего не пишет в систему), ждёт 12 с, затем считает процессорное время процесса за `IdleSec` с окном на «Панели» и
  завершает ТОЛЬКО этот процесс. Флаг пишет в файл отметки (мс от старта процесса), рабочий набор, управляемую кучу, среднюю длительность одного
  опроса монитора, дочерние процессы; `--cycle-pages N` проходит все страницы N раз (утечки, время первой загрузки, худший простой UI).
- Машина: Ryzen 7 9800X3D (8 ядер/16 потоков), NVIDIA, Windows 11 Pro 10.0.26300, .NET 10.0.14. «% ядра» = мс процессорного времени в секунду / 10.
- Числа — медиана/типичные из 2–4 запусков, разброс ±5 %.

## Исходное состояние (до правок)

| Показатель | Значение |
|---|---|
| Процесс → `OnStartup` | 385–440 мс (рантайм, распаковка сжатых сборок single-file) |
| Создание `MainViewModel` (11 страниц) | 70–80 мс |
| Создание `MainWindow` (XAML) | 165–215 мс |
| До первого кадра (интерактивное окно) | 0,97–1,1 с |
| «Панель»: первый замер монитора / проверки готовы | 0,95–1,07 с / 1,32–1,43 с |
| Холодный первый запуск нового exe | +~450 мс (первая распаковка) |
| **Простой на «Панели», окно открыто** | **85–90 мс CPU/с (≈ 9 % одного ядра)** |
| **Простой, окно свёрнуто** | **30 мс CPU/с** (монитор PDH/D3DKMT работал в свёрнутом окне) |
| Рабочий набор / private | 390 / 317 МБ (из них > 170 МБ — драйверные DLL NVIDIA, `nvgpucomp64` 110 МБ; управляемая куча 45 МБ) |
| Дочерние процессы при старте | 2 (`fsutil`, `powershell`) — нормально |
| Утечки при 6 обходах всех страниц | куча после GC плоская 16–20 МБ; рабочий набор выходит на плато ~480 МБ |

## Что нашли и исправили

1. **Горячий цикл отрисовки (главная находка).** Шаблон `ProgressBar` (Theme/Controls.xaml) запускал `Storyboard RepeatBehavior="Forever"`
   при `IsIndeterminate=True`, а индикатор занятости в `MainWindow` (и на Optimize) всегда `IsIndeterminate="True"`, скрытый только `Visibility`. Анимация
   на свёрнутом (Collapsed) элементе продолжает тикать, WPF рендерил ~200 кадров/с в простое. Теперь запускается `MultiTrigger`
   (`IsIndeterminate` И `IsVisible`): видимый вид не изменился, скрытая полоса ничего не рисует.
   Простой: **85 → 18 мс CPU/с** (−79 %).
2. **Монитор «Панели» в свёрнутом окне.** `PageViewModel.SuspendForMinimize/ResumeFromMinimize` (по умолчанию пусто), `MainWindow.StateChanged` вызывает их
   для текущей страницы; `DashboardViewModel` останавливает/перезапускает `LiveMonitor` (PDH/D3DKMT/NVML). Простой свёрнутого окна: **30 → ~1 мс CPU/с**.
   Тесты: `PerfPollingTests` (монитор останавливается при сворачивании и `Deactivate`, не стартует до первой загрузки).
3. **Настройки рантайма:** `ConcurrentGarbageCollection=false` (нет фонового GC-потока), `TieredPGO=false` (нет инструментирования горячих методов).
   Простой **18 → 8–9 мс CPU/с**, процессорное время старта 4,4 → 3,5 с (−20 %), рабочий набор −20 МБ (390 → ~370), время до первого кадра без изменений.
   Суммарно простой на «Панели»: **85–90 → 8–9 мс/с (≈ 10× меньше, 0,05 % всех ядер)**.
4. **Подписки представлений.** Optimize/Restore/Settings/Devices/Drivers-Hardware подписывались на `PropertyChanged` страницы (живёт весь запуск)
   на `DataContextChanged` и не отписывались — каждое посещение страницы оставляло живую подписку мёртвой копии (она же первой «съедала» одноразовый
   фокус `FocusedItem = null`). Теперь подписка только между `Loaded` и `Unloaded` (как уже было в Apps/Services/Tools). Измеримого роста кучи не было
   (дерево страниц невелико: 16–20 МБ после GC и до, и после), это защита от накопления и от «съеденного» фокуса.

## Проверено, менять не нужно

- Сэмпл монитора: 2,7 мс на опрос (1 раз в секунду) — не причина простоя; при уходе со страницы монитор уже останавливался (`Deactivate`).
- Локализация: таблицы en грузятся только при `--lang en`/английском Windows (ленивая, ru-запуск ничего не читает); en добавляет ~30 мс к старту.
- Дочерние процессы при старте: 2 (`fsutil`, `powershell`), по `ProcessRunner`, параллельность уже ограничена `MaxParallelProbes`.
- Заморозка кистей `Colors.xaml` (`po:Freeze`): замер без разницы (старт, память) — не внесено.
- Первая загрузка страниц (в фоне, с индикатором): Optimize 66 мс, Games 80, Maintenance 125, Services 330, Restore 275, Devices 800, Drivers 1,25 с, Apps 2,7 с
  (внешний вызов winget); худший простой UI при построении страницы 20–170 мс (Devices/Apps).
- Размер/сжатие/ReadyToRun: см. `docs/antivirus.md` (88 МБ; без сжатия 156–222 МБ). Не менялось: сжатие отвечает за ~400 мс до `OnStartup`
  (распаковка сборок при каждом запуске) — осознанный размен на размер файла и антивирусный профиль.
- Рабочий набор ~370 МБ: большая часть — драйверные DLL NVIDIA, подгружаемые WPF (Direct3D) и NVML; управляемая куча ~40 МБ. Из приложения не убрать.

## Что осталось

- Холодный старт ≈ 1 с + первая распаковка; ускорить можно только отказом от сжатия single-file (размер ×1,8–2,5) — решение владельца.
- Построение страниц Devices/Apps на UI-потоке (100–170 мс): можно разбить на этапы/виртуализировать карточки, отдельная задача с визуальной проверкой.
- Игровой тикер (`GamesViewModel`, 1 с) работает только во время игрового сеанса; в свёрнутом окне остаётся (данные нужны сеансу).
